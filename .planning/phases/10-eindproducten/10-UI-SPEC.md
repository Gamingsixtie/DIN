## Interaction Contracts

### IC-01: Gap Detection Modal (D-11)

**Trigger:** User clicks "Downloaden (.docx)" button.

**Flow:**
1. On click, compute gaps using `findGaps()` + `getGoalCompletionStatus()`
2. If zero gaps AND zero "volgende cyclus" goals: proceed directly to export (no modal)
3. If gaps or "volgende cyclus" goals exist: show GapDetectionModal overlay

**Modal layout:**
- Backdrop: `fixed inset-0 z-50 bg-black/30 backdrop-blur-sm` (established pattern from CrossAnalyseStep LoadingOverlay)
- Content card: `bg-white rounded-xl shadow-2xl max-w-lg mx-auto mt-[15vh] p-6`
- Title: `text-lg font-bold text-cito-blue mb-4` with text "Exportoverzicht"

**Modal content (two categories):**

Category 1 -- "Volgende cyclus" (informational, not alarming):
- Header: `text-sm font-semibold text-gray-500 uppercase tracking-wide mb-2`
- Copy: "Nog niet uitgewerkt (volgende cyclus)"
- Icon: clock or calendar (gray)
- List: Goal names in `text-sm text-gray-600`, each with bullet

Category 2 -- "Aandachtspunten" (real gaps, worth noting):
- Header: `text-sm font-semibold text-amber-700 uppercase tracking-wide mb-2`
- Copy: "Onvolledige ketens"
- Icon: warning triangle (amber)
- List: Gap descriptions in `text-sm text-amber-800`, each with bullet
- Sub-items: "Baat zonder vermogen", "Vermogen zonder inspanning" with entity name

**If no real gaps exist, Category 2 is hidden.**
**If no "volgende cyclus" goals exist, Category 1 is hidden.**

**Actions (always two buttons):**
- Primary: "Toch exporteren" -- `px-5 py-2.5 bg-cito-blue text-white rounded-lg text-sm font-medium hover:bg-cito-blue-light` (proceeds to export)
- Secondary: "Eerst aanvullen" -- `px-5 py-2.5 border border-gray-300 text-gray-700 rounded-lg text-sm font-medium hover:bg-gray-50` (closes modal, returns to app)
- Button order: Secondary left, Primary right (standard pattern)

**Accessibility:**
- Focus trapped within modal
- Escape key closes modal (same as "Eerst aanvullen")
- Initial focus on "Toch exporteren" (D-11: default is to proceed)

### IC-02: Numbered Section Preview (D-03)

**Behavior:** All Section and SubSection components in the preview receive a number prefix.

**Numbering rules:**
- H1 sections: 1., 2., 3., etc. (auto-increment based on render order)
- H2 subsections: 1.1, 1.2, 2.1, etc. (reset per H1)
- Numbering is computed at ExportStep render time using a simple counter

**Visual treatment:**
- Number prefix is part of the title text: "1. Programmavisie" not "1." as separate element
- Same font size, weight, and color as the section title

**Section order (when all present):**
1. Programmavisie (1.1 Beknopt, 1.2 Uitgebreid)
2. Scope (2.1 Binnen scope, 2.2 Buiten scope)
3. Programmadoelen
4. DIN-Netwerk per Doel
5. Cross-analyse
6. Gap-analyse
7. Hefboomwerking
8. Governance
9. Externe Projecten
10. Sectorale Uitwerking
11. Roadmap

**Optional sections:** If a section has no data (returns null), skip its number. Next section increments from last used number.

### IC-03: DIN Tabel-Flow Visualization (D-06, D-07)

**Trigger:** Rendered in the DIN-Netwerk section of the preview, per doel per sector.

**Layout:**
- Per doel: heading with "Doel {rank}: {name}"
- Per sector within doel: bordered block with sector accent color (left border)
- Within sector: a table with 5 columns: Baat | arrow | Vermogen | arrow | Inspanning

**Table styling (preview -- Tailwind):**
- Table: `w-full border-collapse text-xs`
- Header row: `bg-cito-blue/5 text-cito-blue font-bold text-[10px] uppercase tracking-wide`
- Header cells: Baat (30%), arrow (4%), Vermogen (28%), arrow (4%), Inspanning (34%)
- Arrow cells: centered `text-gray-400` with `\u2192` character
- Data cells: `text-sm text-gray-700 p-2 border-b border-gray-100`
- Benefit cell: `bg-blue-50/50` on first row of chain, empty string on subsequent rows
- Capability cell: plain background, or `bg-[#F0F4FF]` + italic "(gedeeld)" if shared
- Effort cell: domain-colored background from DOMAIN_COLORS map + `[Domein]` label suffix

**Data mapping:**
- Use `buildChainsForSector(session, goal.id, sector)` for chain data
- Filter with `!c.consolidated` and `!e.consolidated` for active items
- For each chain: benefit spans all rows, capability spans its effort rows, each effort is one row
- Unlinked capabilities/efforts shown below chains with muted styling

**Empty state:** If a doel has no chains for any sector, show: "Dit doel is nog niet uitgewerkt voor sector {sector}." in italic gray text.

### IC-04: Export Success Feedback

**Existing pattern (keep):** After successful download, show inline success text "Document gedownload" in `text-xs text-emerald-600 font-medium`, auto-dismiss after 4 seconds.

**Addition:** If export completes after gap-detection modal was shown, also fire toast: `addToast("Programmaplan geexporteerd", "success")`.

### IC-05: Loading State During Export

**Existing pattern (keep):** Button text changes to "Document aanmaken..." with spinner SVG, button is disabled during export.

## Word Document Design Contract

This section specifies the visual contract for the generated Word document (docx library output). The executor uses this alongside the in-app preview contract above.

### Heading Numbering (D-03)

**Implementation:** A mutable `NumberingState` object passed through all section builder functions.

```
{ h1Counter: number, h2Counter: number }
```

- `numberedHeading(text, 'h1', state)`: increments h1Counter, resets h2Counter to 0, returns `heading("{h1Counter}. {text}", HeadingLevel.HEADING_1)`
- `numberedHeading(text, 'h2', state)`: increments h2Counter, returns `heading("{h1Counter}.{h2Counter} {text}", HeadingLevel.HEADING_2)`
- TOC is generated AFTER all sections, reading final numbering state for accuracy

### Consolidation Filtering (D-02)

**Pattern:** At the top of `generateWordDocument()`, create filtered arrays:
```
const activeCaps = session.capabilities.filter(c => !c.consolidated);
const activeEfforts = session.efforts.filter(e => !e.consolidated);
```

Pass `activeCaps` and `activeEfforts` to ALL section functions that render capabilities or efforts.

### Tabel-Flow in Word (D-06, D-07)

**Table structure:** 5 columns (Baat 30% | arrow 4% | Vermogen 28% | arrow 4% | Inspanning 34%)

| Element | Styling |
|---------|---------|
| Header row | shading: `003366` (Cito blue), text: white, bold, size 18 half-pts |
| Arrow cells | centered `\u2192`, bold, size 20 half-pts, color `888888` |
| Benefit cell | shading: `E8F0FE` (light blue) on first row, empty on subsequent |
| Capability cell | plain white; if shared: italic text + shading `E8EDF3` |
| Effort cell | shading: domain color from DOMAIN_COLORS map |
| Effort text | `{title} [{domain label}]` format |
| "Gedeeld" mark | italic "(gedeeld)" suffix on capability/effort text |
| Cell borders | THIN_BORDER (1px, `D0D0D0`) on all sides |
| Cell padding | spacing before: 50, after: 50 (established in styledCell) |

### Gap Analysis in Word (D-12, D-13)

**Two subsections:**
1. "Volgende cyclus" -- bodyText listing goals with status "niet-begonnen", italic, non-alarming
2. "Onvolledige ketens" -- bodyText listing real gaps (started goals with missing links), bold gap type

### Roadmap in Word (D-09)

**If quarters exist:** Table with columns: Inspanning | Domein | Kwartaal | Sector | Status
**If no quarters:** bodyText with italic placeholder: "Kwartaalplanning wordt in een volgende cyclus bepaald."
