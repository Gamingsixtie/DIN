## Decision — focus-doel fallback strategie (R5)

**Fallback voor lege `focusGoal.description`:** val terug op `focusGoal.name`.

**Reden:** KiB-imports (het veruit meest voorkomende pad in productie) leveren altijd een `name`-veld maar niet altijd een `description`. Door op `name` terug te vallen houdt de AI-call context en kan de prompt nog steeds inkleuren (zij het op een kortere bron). Het alternatief — `focusGoal` als `null` doorgeven — levert leeg gekleurde sub-effort adviezen, wat de UX van Phase 18 ondermijnt.

**Transparantie:** de prompt (Plan 03) ontvangt `focusDoel.beschrijving` als string. Of die string afkomstig is van `description` of van `name`-fallback is transparant voor de prompt; kwaliteit van inkleuring is iets lager bij name-fallback (korter, minder ambitie-taal) maar blijft bruikbaar. De prompt bevat een expliciete note dat `beschrijving === naam` een geldige runtime-situatie is die niet in de output benoemd hoeft te worden.

**Niet-overwogen alternatieven:** (a) `description || ""` → lege string zou verwarring geven in prompt; (b) `focusDoel: null` bij lege description → onnodig verlies van inkleuring; (c) fallback op `groep.gezamenlijkeOmschrijving` → minder specifiek dan het doel zelf.

<objective>
