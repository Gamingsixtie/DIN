# Phase 14 — UI Design Contract

> Visual and interaction contract for "Lopende projecten promoveren tot volwaardige inspanningen met splitsing en bevindingen-afleiding". Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>

## Spacing Scale

Declared values (Tailwind 4 defaults, multiples of 4, already used consistently across the codebase):

| Token | Value | Usage in Phase 14 |
|-------|-------|-------------------|
| xs | 4px (`gap-1`, `p-1`) | Icon gaps inside badges, checkbox-label gap in finding cards |
| sm | 8px (`gap-2`, `p-2`) | Inline chip padding (domain chips), badge internal padding |
| md | 16px (`gap-4`, `p-4`) | Default card padding (project card, effort card, finding card) |
| lg | 24px (`gap-6`, `p-6`) | Review panel internal section breaks (between baat-matches / vermogen-matches / efforts / findings) |
| xl | 32px (`gap-8`, `p-8`) | Review panel outer padding when rendered as full-width expandable section |
| 2xl | 48px (`mt-12`) | Not used in this phase |
| 3xl | 64px (`mt-16`) | Not used in this phase |

Exceptions: none. All Phase 14 spacing must snap to this scale — the existing `ExterneProjectenPanel` uses only these values (`p-2`, `p-3`, `p-4`, `gap-2`, `gap-3`, `gap-4`).

Note on `p-3` / `py-3` (12px): already in use in existing panels (`className="px-3 py-3"` — `ExterneProjectenPanel.tsx` §342). 12px is a valid multiple-of-4 step and is the established button/input padding. Treat as `sm+` variant, allowed.

## Typography

Four roles, two weights (regular 400 + semibold 600), Inter font. All Phase 14 text must map to one of these.

| Role | Size | Weight | Line Height | Tailwind class | Usage in Phase 14 |
|------|------|--------|-------------|----------------|-------------------|
| Label | 12px | 600 | 1.4 | `text-xs font-semibold` | Section labels, badge text ("Gepromoveerd", "Lopend project"), domain chip labels, finding type chips |
| Body | 14px | 400 | 1.5 | `text-sm` | Project description, effort description, AI toelichting in finding cards, checkbox labels in baat/vermogen review |
| Subheading | 16px | 600 | 1.4 | `text-base font-semibold` | Effort titles in split preview, benefit/capability match titles |
| Heading | 18px | 600 | 1.3 | `text-lg font-semibold` | Review panel section headers ("Voorgestelde baten", "Voorgestelde vermogens", "Inspanningen-splitsing (1-4)", "Bevindingen") |

No `text-xl` or larger is used inside the review panel — it would compete with the existing DIN mapping step heading hierarchy. The promotion button itself uses `text-sm font-semibold` (matches existing "AI koppeling" button in `ExterneProjectenPanel` §395).

## Color

Phase 14 inherits the Cito + DIN palette from `src/app/globals.css`. No new colors introduced.

| Role | Value | Tailwind token | Usage in Phase 14 |
|------|-------|----------------|-------------------|
| Dominant (60%) | `#f5f7fa` | `bg-cito-bg` (page) + `bg-white` (cards) | Page background, project card background, effort card background |
| Secondary (30%) | `#e2e8f0` + `#f3f4f6` | `border-cito-border`, `bg-gray-50` | Card borders, section dividers, muted inline panels, "gepromoveerd" strikethrough card background |
| Accent (10%) | `#003366` | `bg-cito-blue`, `text-cito-blue`, `border-cito-blue` | Primary promotion CTA background, selected tab underline, focus rings, linked baat/vermogen titles |
| Destructive | `#dc2626` | `text-red-600`, `bg-red-100 text-red-700` | "Terugdraaien" button, AI-validatie error banner |

**Accent reserved for (explicit list — nothing else):**
1. The **"Promoveer naar inspanningen"** primary button on the active project card
2. The **"Bevestig promotie"** primary button at the bottom of the review panel
3. Focus rings on editable effort fields (`focus:ring-1 focus:ring-cito-blue`)
4. The active tab underline inside the review panel (if tabbed layout is chosen — `border-b-2 border-cito-blue`)
5. The title link of a matched existing baat/vermogen in the review list (`text-cito-blue hover:underline`)
6. The "Voeg toe aan DIN" link/button on finding cards (`text-cito-blue`)

**Domein colors (4-way semantic palette, NOT treated as accent):** continue to use `#2563eb` (Mens), `#059669` (Processen), `#7c3aed` (Data & Systemen), `#d97706` (Cultuur) via existing `DOMAIN_CHIP_CHECKED` / `DOMAIN_BORDER_COLORS` constants in `ExterneProjectenPanel.tsx` §48-60. These are data-semantic (which domain does an effort/project belong to) and do not count against the 10% accent budget.

**Gepromoveerd state styling:** a promoted project (shown only via the "Toon gepromoveerde projecten" toggle) uses `bg-gray-50 opacity-60` with a `border-gray-200` and a small `bg-green-100 text-green-700 text-xs font-semibold` "Gepromoveerd" badge in the top-right corner. Matches the existing "buiten scope" pattern at `ExterneProjectenPanel.tsx` §600.

**Findings emphasis color:** Finding cards use a subtle `bg-amber-50 border-amber-200` wash to signal "AI-inzicht, vereist jouw keuze". The accept button inside the finding card still uses the standard `text-cito-blue` accent — the amber is container-only, not an accent override.

## Interaction Contract

### Promotion button placement
- Renders on each **active** project card in `ExterneProjectenPanel` (filter: `!project.promotedAt`).
- Position: bottom-right corner of the card action row, next to any existing Phase 12 actions (AI koppelen). Same button size/padding as existing actions (`px-3 py-2 text-sm font-semibold`).
- Disabled if `project.description` is empty (with tooltip: `Voeg eerst een projectbeschrijving toe.`).

### Review panel surfacing
- **Pattern:** inline expandable section directly below the clicked project card — NOT a modal, NOT a full-page overlay.
- Rationale: the user must still see the source project context while reviewing. An inline panel keeps project + review visible simultaneously on a single scroll, consistent with the existing `AIKoppelingPanel` embedding approach (Phase 12 D-06 pattern).
- Uses the existing `.collapse-wrapper` grid-row transition animation from `globals.css` §41-53.
- Full width of the parent container. Maximum internal width: none (fills panel).

### Loading state
- Project card shows a subtle loading shimmer over the action button area, disabled `Promoveer naar inspanningen` button with spinner + `Bezig met promoveren…` text.
- Loading duration in UI: driven by AI call latency. No artificial delay. No skeleton inside the not-yet-rendered review panel — the panel only mounts once data arrives.
- Use the existing spinner pattern: `<span className="w-5 h-5 border-2 border-white border-t-transparent rounded-full animate-spin" />` (from `ExterneProjectenPanel.tsx` §399).

### Review panel sections — visual layout

Vertical stack, in this order, separated by `gap-6` (24px):

1. **Title + help text** — one line title, one line subtitle, close button (`×`, top-right).
2. **Section 1 — Voorgestelde baten** — list of baat-match cards. Each card has a checkbox (pre-checked per AI recommendation per D-04), the existing baat title (accent color, clickable to scroll in the main DIN view), AI match confidence/reason line (`text-xs text-gray-500`).
3. **Section 2 — Voorgestelde vermogens** — identical card pattern as baten.
4. **Section 3 — Inspanningen-splitsing** — grid of 1-4 effort cards (responsive: `grid-cols-1 md:grid-cols-2`). Each effort card has:
   - Editable title field (`text-base font-semibold`, transparent background, focus ring accent)
   - Editable description field (`text-sm`, textarea, 2 lines default)
   - Domain chip selector (reuse existing `DOMAIN_CHIP_CHECKED` pattern, single-select per effort)
   - Status pill (`text-xs`, defaults to `in_uitvoering`)
   - Quarter picker (`text-xs` select)
   - "Verwijder deze effort" link (`text-xs text-amber-600 hover:text-amber-800 underline`) — only shown when split count > 1
   - Methodiek-warning badge (`bg-amber-50 text-amber-700 text-xs`) if `validateInspanning()` flags the effort
5. **Section 4 — Bevindingen** — stacked finding cards on `bg-amber-50 border-amber-200 rounded-lg`. Each has: type badge (`baat` / `vermogen` / `inspanning` — uses the DIN keten colors: `bg-din-baten`, `bg-din-vermogens`, `bg-din-inspanningen` with white text), beschrijving (`text-sm font-semibold`), toelichting (`text-xs text-gray-600`), and the `Voeg toe aan DIN` button (right-aligned, `text-cito-blue text-sm font-semibold`).
6. **Bottom action bar** — sticky within the panel scroll. `Annuleren` (left, `text-sm text-gray-600 hover:text-gray-900`) + `Bevestig promotie ({N})` (right, primary accent button). The `{N}` updates live as the user toggles baat/vermogen checkboxes or removes split efforts.

### Hit targets
- All clickable buttons, checkboxes, and chip selectors must be ≥ 32px in the smallest tap dimension (achieved via `py-2 px-3` minimum). The "×" close button and inline `Verwijder` links may be smaller since they are mouse-only secondary actions.

### Focus order
- Tab order: close button → section 1 checkboxes (top to bottom) → section 2 checkboxes → section 3 effort cards (title → description → domain → quarter → remove) → section 4 finding "Voeg toe" buttons → Annuleren → Bevestig promotie.

### Responsive behavior
- ≥ 768px (`md:`): Effort cards in 2-column grid. Finding cards in single column.
- < 768px: All sections single-column. Review panel remains inline-expand. Sticky action bar collapses to full-width stacked buttons.
