## Component Inventory

### Focal Point

Primary focal point: the ProjectImportPanel parse button ("Analyseer met AI") -- first visible call to action when the panel is expanded with no projects. This button is the single most prominent interactive element on the screen, using `bg-cito-blue text-white font-semibold` to draw attention. All other elements are secondary in visual weight.

### 1. ProjectImportPanel (new, replaces current ExterneProjectenPanel header area)

**Location:** Inside ExterneProjectenPanel, above the project list.

**Layout:** Two-tab interface within the collapsible panel:
- Tab 1: "Tekst plakken" -- large textarea (min-height 160px)
- Tab 2: "Document uploaden" -- dropzone (reuse SectorWerkStep pattern)

**Visual specs:**
- Tab bar: `text-sm font-semibold`, active tab underline `border-b-2 border-cito-blue text-cito-blue`, inactive `text-gray-500`
- Textarea: `w-full px-3 py-3 text-sm border border-gray-300 rounded-lg focus:outline-none focus:ring-1 focus:ring-cito-blue resize-y`, min-height 160px, placeholder: "Plak hier de klantreis-informatie, projectbeschrijvingen of Miro-export..."
- Dropzone: Reuse exact SectorWerkStep pattern -- `border-2 border-dashed border-gray-300 rounded-lg hover:border-cito-blue hover:bg-blue-50/50`, SVG upload icon, accepts `.docx,.txt,.pdf`
- Parse button: `px-4 py-2 bg-cito-blue text-white text-sm font-semibold rounded-lg hover:bg-cito-blue-light disabled:opacity-50`, label "Analyseer met AI"
- Loading spinner during AI parse: `w-5 h-5 border-2 border-white border-t-transparent rounded-full animate-spin` inline in button

**States:**
- Empty: tabs visible, no content
- Text entered / file uploaded: parse button enabled
- Parsing: button shows spinner + "Bezig met analyseren..."
- Parsed: review cards appear below (see ReviewProjectCard)

### 2. ReviewProjectCard (new)

**Location:** Below the import panel, one card per extracted project.

**Layout:** White card with left domain color stripe.

**Visual specs:**
- Card: `p-4 bg-white border border-gray-200 rounded-lg`, left border 3px solid using primary domain color
- Project name: `text-sm font-semibold text-gray-800`
- Description: `text-xs text-gray-600 mt-1 line-clamp-3`
- Status select: Reuse existing `STATUS_OPTIONS` pattern -- `text-xs px-2 py-1 border border-gray-200 rounded`
- Domain checkboxes row: horizontal flex, each checkbox is a pill-shaped chip

**Domain checkbox chip spec:**
- Unchecked: `px-2 py-1 text-xs rounded-full border border-gray-300 text-gray-500 bg-white cursor-pointer hover:border-gray-400`
- Checked: `px-2 py-1 text-xs rounded-full border font-medium cursor-pointer` with domain-specific colors:
  - Mens: `bg-domain-mens/10 text-domain-mens border-domain-mens/30`
  - Processen: `bg-domain-processen/10 text-domain-processen border-domain-processen/30`
  - Data & Systemen: `bg-domain-data/10 text-domain-data border-domain-data/30`
  - Cultuur: `bg-domain-cultuur/10 text-domain-cultuur border-domain-cultuur/30`

**Action buttons:**
- "Project bevestigen": `text-xs text-cito-blue hover:underline` (confirms single project)
- "Verwijderen": `text-xs text-red-400 hover:text-red-600 opacity-0 group-hover:opacity-100`
- "Alles bevestigen": `px-3 py-2 bg-cito-blue text-white text-xs rounded hover:bg-cito-blue-light` (above card list, confirms all)

**States:**
- Review mode: editable fields, "Project bevestigen" button visible
- Confirmed: card border becomes `border-green-200`, subtle `bg-green-50/30` tint, checkmark icon replaces "Project bevestigen"
- AI warning (D-13): orange left border (`border-l-amber-500`), warning badge in top-right

### 3. AIKoppelingPanel (new)

**Location:** Below confirmed projects, triggered per project or batch.

**Purpose:** Shows AI-suggested project-to-vermogen mappings (per D-06, D-09).

**Layout:** Per project, a row showing: project name on left, arrow, suggested vermogens on right.

**Visual specs:**
- Container: `p-4 bg-blue-50/30 border border-blue-100 rounded-lg`
- Project name: `text-sm font-medium text-gray-700`
- Arrow: `text-gray-400 mx-2` using unicode arrow or SVG
- Vermogen chip: `px-2 py-1 text-xs rounded bg-din-vermogens/10 text-[#0891b2] border border-din-vermogens/20`
- Each vermogen chip has a checkbox/toggle to accept or reject the suggested mapping
- Accepted: chip gets `ring-2 ring-din-vermogens/40` outline
- Rejected: chip becomes `opacity-40 line-through`

**Action buttons:**
- "Bevestig koppelingen": `px-3 py-2 bg-cito-blue text-white text-xs rounded hover:bg-cito-blue-light`
- "Opnieuw analyseren": `text-xs text-gray-500 hover:text-cito-blue` (re-runs AI)

**States:**
- Loading: skeleton pulse placeholders for vermogen chips
- Suggested: chips with toggle states
- Confirmed: container border changes to `border-green-200`, "Gekoppeld" badge visible

### 4. WarningBadge (new, per D-13)

**Location:** Top-right corner of ReviewProjectCard or inline in project list.

**Visual specs:**
- Badge: `px-2 py-1 text-xs font-medium bg-amber-100 text-amber-700 rounded-full`

**Visual specs:**

- Text: "Lopend project"
- Positioned: inline after the effort/project title, same line

### 6. ProjectCard in Inspanningen List (per D-12)

**Location:** Inline among DIN-generated EffortCards in the inspanningen section.

**Visual specs:**

  - Left border: 3px solid `#0066cc` (cito-accent) instead of single domain color
  - LopendProjectBadge in top-right
  - Multi-domain chips row (if multiple domains assigned)
  - Linked vermogens shown as small chips below description
- Non-editable domain/description (imported data), but status is editable

## Interaction Patterns

### Import Flow (per D-01, D-02, following SectorWerkStep pattern)

1. User opens "Lopende projecten" collapsible panel in DINMappingStep
2. User chooses "Tekst plakken" or "Document uploaden" tab
3. User pastes text or uploads file
4. User clicks "Analyseer met AI" button
5. AI parses and returns structured projects (loading state: button spinner + "Bezig met analyseren...")
6. ReviewProjectCards appear with extracted data
7. User reviews each card: edits name, description, selects domains (D-11), adjusts status
8. User confirms individually ("Project bevestigen") or batch ("Alles bevestigen")
9. Confirmed projects are saved to session

### DIN Koppeling Flow (per D-06, D-07, D-09)

1. After projects are confirmed, "Analyseer koppelingen" button appears
2. User clicks button, AI analyzes project descriptions against existing vermogens
3. AIKoppelingPanel shows suggested project-to-vermogen mappings
4. User toggles individual vermogen chips to accept/reject
5. User clicks "Bevestig koppelingen" to save mappings
6. Projects appear inline in inspanningen list with LopendProjectBadge (D-12)

### Warning Flow (per D-13)

1. AI identifies projects that don't clearly fit the DIN network
2. WarningBadge appears on those project cards (amber badge)
3. User hovers/clicks badge to read AI-toelichting
4. User can: (a) reposition project by editing domains/description, or (b) mark as "buiten scope" via a dedicated action

### Collapsible Panel Behavior

- Panel starts collapsed if no projects exist, open if projects > 0 (existing pattern)
- Collapse animation: reuse existing `collapse-wrapper` CSS class with grid-template-rows transition
