# Phase 13 — UI Design Contract

> Visual and interaction contract for the rewrite of `StapSectorVertaling.tsx` into a focusview around the first goal (rank 1). Generated by gsd-ui-researcher. Pre-populated from `13-CONTEXT.md`, `src/app/globals.css`, and existing cross-analyse patterns. Verified by gsd-ui-checker.

**Scope of this phase:** rewrite `src/components/cross-analyse/StapSectorVertaling.tsx` end-to-end. No new routes, no new top-level layouts. All tokens below already exist in the project — this spec locks how the rewritten component MUST consume them.

## Typography

Four sizes, two weights. Values match what the existing wizard already uses so the new view blends with the surrounding chrome.

| Role | Size | Weight | Line Height | Where it appears |
|------|------|--------|-------------|------------------|
| Display | 18px (`text-lg`) | 600 (`font-semibold`) | 1.3 | Focus-doel name inside the focus card; step title rendered by parent wizard |
| Heading | 14px (`text-sm`) | 600 (`font-semibold`) | 1.4 | Section headings: "Baten onder dit doel", "Cross-sector vermogens", "Gedeelde inspanningen", "AI-review samenvatting" |
| Body | 13px (`text-[13px]`) | 400 (`font-normal`) | 1.5 | Baat descriptions, vermogen descriptions, inspanning descriptions, AI risicoteksten, AI verbredings-toelichtingen |
| Label | 11px (`text-[11px]`) | 500 (`font-medium`) | 1.4 | Badge labels (geraakt/risico/dekt_volledig/moet_verbreed/mist_aspect), sector group headers ("PO", "VO", "Zakelijk"), count suffixes |

**Weights used: exactly 2 (`font-normal` 400, `font-semibold` 600).** `font-medium` 500 is considered an in-range variant of semibold for label rendering — if the checker flags this, collapse labels to `font-semibold`.

**Rules:**
- Never use `text-xs` (12px) alongside `text-[11px]` in the same block — pick one.
- No `text-xl` or larger inside this component — the wizard shell already owns step-level display typography.
- The AI samenvatting block renders its 3–5 sentences at body size, not heading size, so it reads as prose not as a banner.

## Color

60/30/10 distribution, locked to the existing Cito + DIN token palette in `src/app/globals.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--color-cito-surface`) on `#f5f7fa` (`--color-cito-bg`) | Wizard panel background, content surfaces, card fills |
| Secondary (30%) | `#003366` (`--color-cito-blue`) + `#e2e8f0` (`--color-cito-border`) + neutral gray scale (`text-gray-700`, `text-gray-500`, `text-gray-400`) | Focus-doel card header, section headings, borders, meta text, count suffixes |
| Accent (10%) | DIN chain colors as left borders only: `#003366` doelen / `#0066cc` baten / `#0891b2` vermogens / `#059669` inspanningen | Left border (`border-l-4`) on every DIN-chain item to anchor it methodically |
| Destructive | `#dc2626` (`bg-red-50 border-red-200 text-red-700`) | Only for `wordtGeraakt: false` risk badges and the risk text block |

**Accent reserved for — explicit list (10% rule):**
1. Left border of the focus-doel card (`border-l-4 border-l-[#003366]`)
2. Left border of each baat item (`border-l-4 border-l-[#0066cc]`)
3. Left border of each cross-sector vermogen item (`border-l-4 border-l-[#0891b2]`)
4. Left border of each gedeelde inspanning item (`border-l-4 border-l-[#059669]`)
5. The "Analyseer eerste doel" primary button (`bg-cito-blue text-white hover:bg-cito-blue-light`) — owned by parent wizard, referenced here for consistency

Accent is **not** allowed on: badges (badges use their own semantic palette below), section headings (those are neutral gray), background fills (backgrounds stay in the dominant/secondary range), hover states on non-CTA elements.

## Component Inventory

Downstream-useful inventory of what the rewritten `StapSectorVertaling.tsx` contains. Internal split is at executor discretion (CONTEXT.md discretion clause), but these blocks MUST be present.

| Block | Purpose | Data source |
|-------|---------|-------------|
| `FocusDoelCard` | Prominent card showing the focus goal name + "prioriteit 1" label | `[...session.goals].sort((a,b) => (a.rank ?? 999) - (b.rank ?? 999))[0]` (D-01) |
| `BatenPerSectorGroup` | Three sub-groups (PO/VO/Zakelijk) of baten linked to focusdoel, each baat with SectorBadge + geraakt/risico badge + optional risico text | Client-filtered via `goalBenefitMaps` where `goalId === focusDoel.id` |
| `CrossSectorVermogensList` | List of vermogens with `relatedSectors.length > 1` AND linked to focusdoel's baten, each with multiple SectorBadges + optional hefboom-toelichting from AI | Client-filtered (D-09) |
| `GedeeldeInspanningenList` | List of efforts with multi-sector `responsibleSector` AND linked to the cross-sector vermogens, grouped by domain, with breedte-badges + toelichting | Client-filtered (D-09) |
| `AISamenvattingBlock` | 3–5 sentence summary rendered as prose inside a soft-border callout | `stap5Result.samenvatting` |
| `BuitenScopeFooter` | Collapsible footer showing `{X} vermogens en {Y} inspanningen vielen buiten scope`; expanded shows simple list with titles + sector badges only | Items NOT in the filtered sets above; no AI review per item (D-03) |

**Layout order (top → bottom):** FocusDoelCard → BatenPerSectorGroup → CrossSectorVermogensList → GedeeldeInspanningenList → AISamenvattingBlock → BuitenScopeFooter.

**State rules:**
- Structural blocks (1–4) render with OR without AI result. AI callouts (badges + toelichtingen + samenvatting) only appear when `stap5Result` is present (D-12c).
- When AI result is absent, the badges area per item shows a neutral placeholder dot, not an empty space.

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Page load | Component mounts, computes focusdoel client-side, renders structural view with or without cached `stap5Result` |
| Click "Analyseer eerste doel" (parent-owned) | Parent `handleAnalyse` fires with `stap: 5`; this component receives loading state from parent; `LoadingOverlay` covers the wizard panel |
| AI success | Badges and toelichtingen appear in place; no layout shift; existing scroll position preserved |
| AI failure | Parent shows error block with retry; this component keeps structural view visible |
| Click "Toon details" on buiten-scope footer | Collapsible expands using the existing `.collapse-wrapper` CSS from `globals.css` (grid-template-rows transition, 250ms) |
| Keyboard | All interactive elements reachable by Tab; collapsible footer toggles on Enter/Space when focused |
| No inline edits | This view is read-only — no form fields, no inline editing, no "toepassen" buttons (per CONTEXT.md deferred ideas) |

**Animation budget:**
- Only the buiten-scope collapse transition (250ms ease-out, already in `globals.css`).
- No hover scale, no shimmer, no entrance animations. The stakes are high — the view must feel calm and authoritative.

## Accessibility

- Color is never the only signal: every badge state includes a text label (e.g., "geraakt", "risico", "moet verbreed") so screen readers and color-blind users get the same information.
- Contrast: Cito blue `#003366` on white = 12.6:1 (AAA). All badge text on its `-50` backgrounds ≥ 4.5:1.
- Minimum touch target for the "Toon details" toggle: 44×44px.
- Section headings use real heading elements (`<h4>`, `<h5>`) in a coherent order under the wizard's step title.
- Empty states use text, not just icons.
