## Interaction Contracts

### Suggestie Adoption Flow

1. User sees suggestiepaneel (expanded by default on first view)
2. User clicks [+] on a suggestion
3. Immediately: suggestion visual changes to adopted state (line-through, opacity-50)
4. Immediately: new DINBenefit created in session with description from suggestion
5. Immediately: goalBenefitMap entry created linking new benefit to active goal
6. New BenefitCard appears in the benefits list below (existing rendering handles this)
7. No loading state needed -- operation is synchronous (localStorage-first)

### Batch Adoption Flow

1. User clicks "Alle suggesties overnemen"
2. All unadopted suggestions are adopted in sequence
3. Each creates a benefit + goalBenefitMap entry
4. All suggestion items show adopted state simultaneously
5. Batch button disappears (all adopted)

### Collapse/Expand Suggestiepaneel

1. User clicks header bar
2. Content area collapses/expands using `.collapse-wrapper` CSS animation (0.25s ease-out)
3. Chevron rotates (right = collapsed, down = expanded)
4. Collapsed state does NOT persist across sector switches -- panel resets to expanded when switching sectors

### Analysis Card Display (SectorWerkStep)

No interaction changes. Existing behavior preserved:
- Cards render immediately from typed object (no parse step)
- "Sluiten" button removes analysis from local state and session
- "Opnieuw analyseren" re-triggers AI analysis

### Migration on Session Load

1. Session loads from localStorage
2. For each entry in sectorAnalyses:
   - If value is object: validate against AISectorplanAnalyseSchema. If valid, keep. If invalid, remove.
   - If value is string: try JSON.parse + validate. If valid, migrate to object. If invalid, remove and show toast.
3. If any entries were removed: show warning toast per removed sector

## Phase-Specific Design Notes

### What stays the same
- SectorWerkStep analysis card visual design is preserved exactly (same borders, colors, spacing, icons)
- Domain color mapping is reused from existing constants (DOMAIN_DOT_COLORS, etc.)
- Card interaction patterns (expand/collapse) follow existing `.collapse-wrapper` CSS
- Toast system from Phase 2 is reused for migration warnings
- createBenefit() from din-service.ts handles all benefit creation (correct ID generation, default profiel values)

### What is new
- SectorwerkSuggestiePanel component in DIN-mapping step
- Adopted suggestion visual state (line-through + opacity)
- Batch adoption button when >= 3 suggestions
- Migration toast for legacy string data

### Design rationale
- The suggestie panel uses `bg-blue-50/50` with `border-blue-200` to visually associate it with the "baten" category color (blue), since it exclusively shows baten suggestions.
- The [+] button uses `bg-cito-blue` (primary accent) because adopting a suggestion is the primary action in this context. The round shape and small size (28px) distinguish it from full CTAs.
- Adopted suggestions remain visible (not removed) per D-05, so the user can reference what they already adopted and maintain mental context.
